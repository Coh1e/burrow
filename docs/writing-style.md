# 写作标准

## CLI 和机器读文本

`--json` 的字段、操作名、状态值与退出码属于调用方使用的接口。修改接口时同步更新文档、测试与调用方，并按相关 ADR 评审。先用行为测试固定新文本的含义与形状。

- 新增稳定错误码使用小写 kebab-case。发布后保留每个码的含义。诊断说明本次失败的对象、动作及调用者可执行的下一步。
- 同一状态用相同的句式。采用主动语态和现在时，一句写一个指令，去除尾随空格。
- 记录时间、字节数或文本偏移时给出单位。

使用命令帮助中的拼写，例如用 `source add` 登记包源，用 `install` 安装包，用 `--dry-run` 预览。描述 Blueprint 时使用项目术语。[原生命令](../brw/README.md) · [术语表](../GLOSSARY.md)

## 人类读文本

中文使用短句，一句一个指令。条件写在指令前。同一概念在一篇文档中使用同一个词。标题用名词短语，列表项以动词或名词开头，保持平行。

文档中的测量值附上产生它的命令或脚本路径，注明修订及运行条件。README 说明安装、构建、常用命令和能力边界，验收细节链接到对应记录。
